# Расчёт ресурсов для микросервисного приложения

## Исходные данные

| Компонент | Ресурсы на копию | Количество копий |
|-----------|------------------|------------------|
| База данных (отказоустойчивая) | 4 ГБ ОЗУ, 1 ядро CPU | 3 |
| Кэш (отказоустойчивый) | 4 ГБ ОЗУ, 1 ядро CPU | 3 |
| Фронтенд | 50 МБ ОЗУ (0.05 ГБ), 0.2 ядра CPU | 5 |
| Бекенд | 600 МБ ОЗУ (0.6 ГБ), 1 ядро CPU | 10 |

## Суммарные требования к ресурсам

### CPU

- База данных: 3 × 1 = **3 ядра**
- Кэш: 3 × 1 = **3 ядра**
- Фронтенд: 5 × 0.2 = **1 ядро**
- Бекенд: 10 × 1 = **10 ядер**

**Итого CPU: 17 ядер**

### RAM

- База данных: 3 × 4 ГБ = **12 ГБ**
- Кэш: 3 × 4 ГБ = **12 ГБ**
- Фронтенд: 5 × 0.05 ГБ = **0.25 ГБ**
- Бекенд: 10 × 0.6 ГБ = **6 ГБ**

**Итого RAM: 30.25 ГБ**

## Учёт служебных ресурсов

На каждой ноде необходимо резервировать ресурсы для операционной системы, kubelet, kube-proxy и других системных компонентов Kubernetes. Примем следующие резервы:

- **CPU:** 1 ядро на ноду
- **RAM:** 2 ГБ на ноду

Таким образом, полезная ёмкость каждой ноды уменьшается на эти значения.

## Выбор параметров нод и их количества

Предлагается использовать рабочие ноды со следующими характеристиками:

- **CPU:** 8 ядер
- **RAM:** 16 ГБ

С учётом служебных ресурсов доступно для приложений:

- **CPU:** 8 − 1 = **7 ядер**
- **RAM:** 16 − 2 = **14 ГБ**

Минимальное количество нод, обеспечивающее требуемые ресурсы при выходе из строя одной ноды, рассчитывается из условия, что при N−1 работающих нодах суммарные ресурсы покрывают потребности:

- **CPU:** (N−1) × 7 ≥ 17
- **RAM:** (N−1) × 14 ≥ 30.25

Решая неравенства:

- N = 4: 3 × 7 = 21 ≥ 17; 3 × 14 = 42 ≥ 30.25 → подходит
- N = 3: 2 × 7 = 14 < 17 → не подходит

**Вывод:** необходимо **4 рабочие ноды** с параметрами **8 CPU / 16 ГБ RAM** каждая.

## Проверка запаса при отказе одной ноды

При отказе одной ноды остаются 3 рабочие ноды, которые предоставляют:

- **CPU:** 3 × 7 = **21 ядро** (при требуемых 17)
- **RAM:** 3 × 14 = **42 ГБ** (при требуемых 30.25)

Запас:

- CPU: 21 − 17 = **4 ядра**
- RAM: 42 − 30.25 = **11.75 ГБ**

Этого достаточно для перезапуска подов с упавшей ноды на оставшихся.

## Итоговая конфигурация

| Параметр | Значение |
|----------|----------|
| Количество рабочих нод | 4 |
| CPU на ноду | 8 ядер |
| RAM на ноду | 16 ГБ |
| Резерв на служебные нужды | 1 ядро, 2 ГБ на ноду |
| Полезная ёмкость кластера (при всех нодах) | 4 × (7 CPU + 14 ГБ) = 28 CPU, 56 ГБ |
| Ёмкость при отказе одной ноды | 21 CPU, 42 ГБ |
| Требуемые ресурсы | 17 CPU, 30.25 ГБ |

**Рекомендация:** развернуть 4 рабочие ноды с 8 CPU / 16 ГБ RAM. В качестве control-plane можно использовать отдельные ноды (например, 3 мастер-ноды с 2 CPU / 4 ГБ), но они не учитываются в расчёте рабочих нод. Если требуется полная отказоустойчивость управляющего слоя, добавить три мастер-ноды. Такой конфигурации достаточно для работы всех компонентов с запасом на отказ одной рабочей ноды.
