# Домашнее задание: Установка кластера Kubernetes с 1 master node

## Цель

Развернуть кластер Kubernetes, состоящий из 1 master node и 4 worker nodes. В качестве CRI используется containerd, etcd запускается на master-ноде. Способ установки выбран самостоятельно.

## Выбранный способ установки

Был выбран **kind (Kubernetes in Docker)** — инструмент для запуска локальных кластеров Kubernetes внутри Docker-контейнеров. Такой подход позволяет имитировать отдельные узлы и полностью соответствует требованиям задания.

## Выполненные шаги

1. Установлен Docker и настроены права текущего пользователя на работу с Docker.
2. Установлен `kubectl` (через snap) и `kind` (бинарник с GitHub).
3. Создан конфигурационный файл `kind-config.yaml`, описывающий 5 узлов:
   - 1 узел с ролью `control-plane` (мастер-нода);
   - 4 узла с ролью `worker` (рабочие ноды).
4. Кластер создан командой `kind create cluster --config kind-config.yaml`.
5. Проверены узлы и системные поды.

## Результат

Кластер успешно развёрнут. Все 5 узлов находятся в статусе `Ready`. Системные компоненты (etcd, kube-apiserver, kube-controller-manager, kube-scheduler, coredns, kindnet, kube-proxy) работают. В процессе эксплуатации возникла временная ошибка с одним из подов `kube-proxy` (too many open files), которая была устранена путём увеличения лимитов `fs.inotify` и пересоздания пода.

## Примечание

Внутри kind каждый узел использует containerd как container runtime. Это автоматически обеспечивает выполнение требования по CRI. etcd запускается только на control-plane узле, что соответствует заданию.
