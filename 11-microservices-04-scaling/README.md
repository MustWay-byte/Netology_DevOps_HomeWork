## Задача 1: Кластеризация

### Предлагаемое решение

Для развёртывания, запуска и управления приложениями в микросервисной архитектуре предлагается использовать **Kubernetes** в связке с **Istio** (service mesh) и **Helm** для управления конфигурациями и деплоем. Для безопасного хранения чувствительных данных используется **HashiCorp Vault** (или встроенные Kubernetes Secrets с использованием Sealed Secrets).

| Компонент | Назначение |
|-----------|------------|
| **Kubernetes** | Оркестрация контейнеров, управление жизненным циклом, автомасштабирование, разделение ресурсов, конфигурирование через переменные окружения. |
| **Istio** | Обнаружение сервисов, маршрутизация трафика, балансировка, mTLS, наблюдаемость. |
| **Helm** | Управление пакетами приложений, шаблонизация манифестов, версионирование релизов. |
| **Vault / Sealed Secrets** | Хранение и управление секретами (пароли, ключи, токены). |

### Как обеспечиваются требования

1. **Поддержка контейнеров**  
   Kubernetes является стандартом де-факто для оркестрации контейнеров. Поддерживает Docker, containerd, CRI-O и другие runtime. Каждый микросервис упаковывается в контейнер и запускается как Pod.

2. **Обнаружение сервисов и маршрутизация запросов**  
   Istio предоставляет service mesh: автоматическое обнаружение сервисов через Kubernetes Service, гибкую маршрутизацию (по путям, заголовкам, версиям), балансировку нагрузки, retry, timeout, circuit breaking. Входящий трафик управляется через Istio Ingress Gateway.

3. **Горизонтальное масштабирование**  
   Kubernetes поддерживает горизонтальное масштабирование через ReplicaSet, Deployment. Количество реплик задаётся вручную или автоматически (HPA).

4. **Автоматическое масштабирование**  
   Horizontal Pod Autoscaler (HPA) масштабирует поды на основе CPU, памяти или custom-метрик. Vertical Pod Autoscaler (VPA) регулирует ресурсы подов. Также можно использовать KEDA для событийно-ориентированного масштабирования.

5. **Явное разделение ресурсов, доступных извне и внутри системы**  
   - Внутренние сервисы доступны через ClusterIP (только внутри кластера).  
   - Внешние через NodePort, LoadBalancer или Ingress.  
   - Istio Ingress Gateway контролирует входящий трафик, а Egress – исходящий.  
   - Network Policies ограничивают сетевой доступ между namespace/подами.  
   - Resource Quotas и Limit Ranges разделяют вычислительные ресурсы между командами/проектами.

6. **Конфигурирование приложений с помощью переменных среды**  
   Kubernetes позволяет задавать переменные окружения через ConfigMap и Secrets. ConfigMap хранит несекретные параметры, а Secrets – чувствительные данные (пароли, ключи). Secrets монтируются как переменные окружения или файлы.

7. **Безопасное хранение чувствительных данных**  
   - **Kubernetes Secrets** хранят секреты в etcd (можно включить шифрование).  
   - **Sealed Secrets** позволяют хранить зашифрованные секреты в Git.  
   - **HashiCorp Vault** предоставляет централизованное управление секретами, динамические секреты, аудит, интеграцию с Kubernetes через sidecar/init-контейнеры.

### Принципы взаимодействия

1. **Разработчик** описывает приложение в `Dockerfile`, Helm-чарт содержит Kubernetes-манифесты (Deployment, Service, ConfigMap, Secret).
2. **CI/CD пайплайн** собирает Docker-образ, публикует его в Registry, затем Helm обновляет релиз в кластере.
3. **Kubernetes** запускает поды, управляет репликами, прокидывает переменные окружения из ConfigMap/Secrets.
4. **Istio** автоматически обнаруживает новые сервисы, настраивает маршруты, применяет политики безопасности и наблюдаемость.
5. **HPA** мониторит метрики и масштабирует поды при необходимости.
6. **Ingress Gateway** принимает внешний трафик и маршрутизирует его внутрь mesh.

### Почему выбрана эта архитектура

- **Kubernetes** – самый распространённый оркестратор, поддерживаемый всеми облачными провайдерами (AWS EKS, Azure AKS, Google GKE, self-hosted). Обеспечивает все требования из коробки или с минимальными дополнениями.
- **Istio** добавляет продвинутую маршрутизацию и безопасность, которые необходимы для сложных микросервисных систем.
- **Helm** упрощает управление жизненным циклом приложений, повторяемость деплоев и версионирование.
- **Vault** решает задачу безопасного хранения секретов более гибко, чем нативные Kubernetes Secrets.

### Альтернативы

- **Docker Swarm** – проще, но ограничен в возможностях масштабирования и маршрутизации.
- **Nomad** – хорош, но менее распространён и имеет меньше интеграций.
- **AWS ECS** – удобно в AWS, но привязывает к вендору и не имеет богатых возможностей service mesh.

Таким образом, предложенное решение полностью закрывает все требования и является промышленным стандартом для микросервисной архитектуры.
